## 互斥锁与可重入锁的区别

- 互斥锁（Lock）：同一时刻只能有一个线程获得锁，其他线程必须等待锁释放后才能获得。若一个线程已经获得锁，再次尝试获取会导致死锁（阻塞自身）。适用于简单的临界区保护。

- 可重入锁（RLock）：同一线程可以多次获得锁，每获取一次计数加一，释放一次计数减一，直到计数为零才真正释放锁。适用于递归调用或同一线程多次进入临界区的场景，避免死锁。

**示例：**
```python
import threading
lock = threading.Lock()
rlock = threading.RLock()

def func_with_lock():
    lock.acquire()
    # lock.acquire()  # 再次获取会死锁
    lock.release()

def func_with_rlock():
    rlock.acquire()
    rlock.acquire()  # 可多次获取，无死锁
    rlock.release()
    rlock.release()
```

**总结：**
- 互斥锁适合简单场景，性能高。
- 可重入锁适合复杂嵌套或递归场景，避免死锁。

## 可重入锁的典型使用场景

可重入锁（RLock）主要用于以下场景：
1. **递归调用**：递归函数内部多次尝试获取同一个锁，若用互斥锁会死锁。
2. **嵌套锁定**：同一线程在多个方法或代码块中重复获取同一个锁（如类方法间互相调用且都加锁），避免死锁。
3. **复杂业务逻辑**：需要在同一线程内多次进入临界区，且每次都需加锁。

**示例：递归场景**
```python
import threading
rlock = threading.RLock()

def recursive(n):
    rlock.acquire()
    print(f"Level {n}")
    if n > 0:
        recursive(n-1)
    rlock.release()

recursive(3)
```

**示例：嵌套锁定场景**
```python
import threading
class Counter:
    def __init__(self):
        self.rlock = threading.RLock()
        self.value = 0
    def increment(self):
        self.rlock.acquire()
        self.value += 1
        self.rlock.release()
    def double_increment(self):
        self.rlock.acquire()
        self.increment()  # 内部再次获取同一个锁
        self.increment()
        self.rlock.release()
```

**总结：**
- 可重入锁适合递归、嵌套加锁等复杂场景，能避免同一线程因重复加锁导致死锁。

## 实际场景：日志写入的线程安全

在多线程环境下，多个线程同时写入同一个日志文件，必须保证写入操作的原子性，否则日志内容会混乱。可重入锁（RLock）可以用于保护整个写入过程，即使日志写入函数内部还会调用其他需要加锁的操作，也不会死锁。

**示例：多线程安全写日志**
```python
import threading
import time
import random

class SafeLogger:
    def __init__(self, filename):
        self.rlock = threading.RLock()
        self.filename = filename
    def write_log(self, msg):
        self.rlock.acquire()
        try:
            with open(self.filename, 'a', encoding='utf-8') as f:
                f.write(msg + '\n')
        finally:
            self.rlock.release()
    def log_with_timestamp(self, msg):
        self.rlock.acquire()
        try:
            timestamp = time.strftime('%Y-%m-%d %H:%M:%S')
            self.write_log(f'[{timestamp}] {msg}')  # 内部再次加锁
        finally:
            self.rlock.release()

logger = SafeLogger('thread_log.txt')

def worker(tid):
    for i in range(3):
        logger.log_with_timestamp(f'Thread-{tid} message {i}')
        time.sleep(random.uniform(0.1, 0.5))

threads = [threading.Thread(target=worker, args=(i,)) for i in range(5)]
for t in threads:
    t.start()
for t in threads:
    t.join()
```

**说明：**
- `log_with_timestamp` 外层加锁，内部调用 `write_log` 再次加锁，RLock 保证不会死锁。
- 多线程写入日志时，内容不会交叉混乱，保证了日志的完整性和线程安全。

## 分布式系统下的日志写入与 Python logger 的锁机制

### 分布式日志写入
在分布式系统中，多台机器同时写入同一个日志文件，不能依赖本地锁（如 RLock），因为锁只在本地进程有效。此时需要：
- 使用分布式锁（如 Redis、ZooKeeper 等）来协调多台机器的写入。
- 更常见做法是每台机器写本地日志，集中收集（如 ELK、Fluentd、Kafka 等日志系统），避免直接共享文件。
- 若必须共享文件，可通过网络文件系统（NFS）+分布式锁，但性能和可靠性较差。

### Python 标准 logger 的锁机制
- Python 的 `logging` 标准库在多线程环境下是线程安全的。
- `logging` 的 `FileHandler` 内部使用了 `threading.RLock`，保证多线程写日志不会交叉。
- 但 `logging` 并不支持多进程或分布式环境下的日志写入安全。多进程需用 `QueueHandler` 或第三方库（如 concurrent-log-handler），分布式需用专门的日志收集系统。

**源码片段（简化）：**
```python
# logging/__init__.py
class FileHandler:
    def __init__(self, ...):
        ...
        self.lock = threading.RLock()
    def emit(self, record):
        self.lock.acquire()
        try:
            ... # 写文件
        finally:
            self.lock.release()
```

**总结：**
- 本地多线程写日志，Python logger 已自动加锁，无需手动处理。
- 多进程或分布式场景需用专门方案，不能依赖本地锁。
